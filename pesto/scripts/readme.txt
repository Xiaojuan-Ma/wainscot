1. files
pesto_clustering.py
input: a DAG generated by Baechi (only_forward = True)
output: a DAG after iterative merging.
For instance, if edge 2 -> 3 is merged, the new node will be '2_3'. Therefore, the node name has the merge info
edges that point to the old endpoints will point to the merged node with the edge attribute 'num_bytes' aggregated

satisfying_colocation_constraint.py
input: the merged DAG
output: a csv file with headers 'op_nums,op_ids,colocation_group': this file will be used by Wainscot
        1. the value in colocation_group column does not have meaning, just some index to differentiate different
            colocation groups
        2. the op_ids are the operators ids in this colocation group
        3. op_nums is the number of ops in op_ids
        4. the order matters: this is the readjusted 'topological order' that respect the colocation constraint

pesto_data: all data, for each model, gnmet_v2, transformer, nasnet_mobile, pnasnet_mobile, there are 3 files:
        1. graph output by Baechi: ...colocation_graph_pesto....pkl
        2. merged_G..pkl : after applying the clustering algo, the output of pesto_clustering.py
        3. ordered_info.csv : output of satisfying_colocation_constraint.py: used by Wainscot

3. workflow of Pesto:
    clustering --> linear programming (respect TensorFlow colocation constraint by setting nodes in the same colocation with the same device)
                   workflow of Pesto_Clu:
    clustering --> topological sort --> manully reindex to respect TF colocation constraint: move nodes in the
                                        same colocation right after the first appereance of the node in this group
                                        (similiar to one of Baechi's approach), then treat those nodes as a single one.
                                        The network size will be further be reduced.
